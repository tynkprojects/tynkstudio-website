Доп. интеграции

Expo (EAS Build / Submit)

Если приложение написано на React Native через Expo — EAS (Expo Application Services) делает то же, что для Pawnia делает Codemagic: собирает и подписывает сборку в облаке и отправляет её в App Store Connect / Google Play. Это альтернатива шагам 1.2–1.3 и 2.2 (сертификаты, загрузка билда), а не отдельная новая часть пути.

🔗 EAS не заменяет Часть 1 и Часть 2 этого мануала целиком — запись приложения в App Store Connect (1.1) и в Google Play Console (2.1), его метаданные и App Privacy/Data Safety (1.4, 2.3) всё равно настраиваются там же, руками, один раз.
1

Установка и первый вход

npm install -g eas-cli
eas login

Дальше, из папки проекта:

eas build:configure

Эта команда создаёт eas.json с профилями сборки (например, development, preview, production) — отдельными наборами настроек для теста и для публикации.

📚 EAS Build — обзор и eas.json: профили сборки — официальная документация Expo.
2

Сборка в облаке

eas build --platform ios
eas build --platform android

Сборка идёт на серверах Expo — Mac для iOS-сборки не нужен. Сертификаты и profiles (наш шаг 1.2) EAS может сгенерировать и хранить сама, либо использовать уже существующие — при первом запуске она спросит.

3

Отправка в стор

eas submit --platform ios
eas submit --platform android

На iOS билд уходит в App Store Connect и становится доступен в TestFlight (наш шаг 1.3) обычно за 10–15 минут. На Android — во внутреннее тестирование Google Play (наш шаг 2.2). Дальше — те же шаги 1.5/2.4 этого мануала: выбрать билд у версии и отправить на ревью.

Можно объединить всё в одну команду:

eas build --auto-submit
📚 EAS Submit → iOS и EAS Submit → Android — официальная документация Expo.
🚫 EAS всё равно должна знать твой Apple Team ID / ASC API Key и Google Play service account (тот же, что мы создавали для RevenueCat) — это не отдельные учётки, а доступ к тем же аккаунтам из Части 1 и 2.

Часть 1 · Apple

1.2 Сертификаты и profiles

У этого шага нет своего экрана в App Store Connect — подпись сборки происходит либо в Xcode на твоём Mac, либо (что сейчас используется для Pawnia) автоматически через CI-сервис вроде Codemagic или Xcode Cloud. Здесь — что это такое и на что обратить внимание, без привязки к конкретному интерфейсу.

1

Что вообще подписывается и зачем

Apple не пускает на устройства и в App Store ничем не подписанный код. Нужны три вещи, выпущенные через твой Apple Developer аккаунт:

  • Сертификат распространения (Distribution Certificate) — подтверждает, что сборку собрал именно ты/твоя команда.
  • App ID — тот самый Bundle ID, который мы указали при создании записи приложения в шаге 1.1 (например, com.yourcompany.yourapp).
  • Provisioning Profile — связывает сертификат, App ID и (для тестовых сборок) конкретные устройства в один файл, который зашивается в собранный .ipa.
2

Два способа получить всё это

Вручную, через Xcode: в настройках проекта включаешь «Automatically manage signing», выбираешь свою команду (Team) — Xcode сам создаёт и скачивает сертификат и profile при каждой сборке. Подходит, если собираешь на одной машине.

Через CI (Codemagic, Xcode Cloud, Fastlane match и т.п.): сертификат и profile генерируются и хранятся на стороне сервиса, привязываются к App Store Connect через API-ключ (App Store Connect API Key, создаётся в Users and Access → Integrations). Так работает текущая сборка Pawnia — сборка 1.1.20/229 была собрана и подписана Codemagic, а не вручную.

💡 Если используешь CI — тебе достаточно один раз создать App Store Connect API Key (Users and Access → Integrations → App Store Connect API) и отдать его сервису. Дальше сертификаты/profiles обновляются автоматически, без твоего участия.
3

Частые проблемы

  • Сертификат просрочен (действует 1 год) — новая сборка перестаёт собираться, пока не перевыпустишь.
  • Bundle ID в Xcode/CI не совпадает с тем, что создан в App Store Connect на шаге 1.1 — сборка загрузится с ошибкой привязки.
  • Несколько разработчиков используют разные сертификаты без общего хранилища (Fastlane match решает это централизованным репозиторием сертификатов).
📚 Если настраиваешь вручную в Xcode — официальный путь: Create a certificate signing request и Create a provisioning profile в документации Apple Developer.

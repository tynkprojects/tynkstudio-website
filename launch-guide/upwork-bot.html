AI-бот для Telegram или WhatsApp

Бот отвечает клиентам нашего клиента по его материалам (FAQ, прайс, сайт), а в старших пакетах ещё записывает на приём, собирает заявки в Google Таблицу и передаёт разговор живому человеку. Всё работает на аккаунтах клиента: его сервер, его ключ ИИ, его бот. Мы строим, настраиваем и передаём.

Как устроен бот (наш стандарт)

Код
Небольшой сервис на Node.js. Приватный репозиторий github.com/tynkprojects/client-имя-bot. Пишет Claude.
Сервер
VPS клиента, обычно Hetzner Cloud, самый маленький Arm-сервер, Ubuntu 24.04, расположение в ЕС. Платит клиент. Мы заходим по SSH-ключу Николая.
ИИ
Ключ API клиента (Anthropic или OpenAI) с месячным лимитом расходов, который ставит сам клиент.
Знания бота
Google Doc клиента, опубликованный в интернете как текст (Файл → Поделиться → Опубликовать в интернете). Клиент правит документ — бот подхватывает изменения. Так клиент сам обновляет знания без нас.
Telegram
Бот создаётся у клиента через @BotFather. Работает без домена.
WhatsApp
WhatsApp Cloud API от Meta на бизнес-аккаунте клиента. Нужен поддомен клиента (например bot.client.com) для защищённого адреса вебхука.
Таблица заявок
Google Таблица клиента + маленький скрипт Apps Script внутри неё (клиент вставляет наш код и даёт нам ссылку). Без сервисных аккаунтов и Google Cloud.
Секреты
Токен бота, ключ ИИ, токен WhatsApp — клиент присылает одноразовыми ссылками → «Пароли» Николая → файл .env на сервере. Claude их не видит.

Что клиент присылает в требованиях

  1. Чем занимается бизнес, что должен делать бот, главные вопросы и задачи, канал (Telegram или WhatsApp).
  2. Материалы, которые бот должен знать (FAQ, прайс, сайт, документы), и инструменты для подключения: Google Таблица, календарь, CRM.

Аккаунты и ключи просим на шаге 2, после согласования плана: сначала клиент должен понять, что именно он подключает.

2Аккаунты и ключи от клиентаКлиент Николай

Отправь клиенту инструкцию одним сообщением (ниже, оставь только нужные пункты). Каждый ключ клиент присылает отдельной одноразовой ссылкой onetimesecret.com. Ты открываешь ссылку и сразу сохраняешь в «Пароли»: Upwork · Клиент · Telegram token, … · AI key и т.д.

Перед отправкой возьми свой публичный SSH-ключ (его можно показывать, это не пароль). В Терминале на Mac:

cat ~/.ssh/id_ed25519.pub

Должна вывестись одна строка, начинается с ssh-ed25519 и заканчивается твоим именем/email. Если пишет «No such file» — скажи Claude, он даст команду, чтобы создать ключ.

4Развёртывание на сервере клиентаНиколай Claude

Ты выполняешь команды в Терминале на Mac, Claude их даёт — у каждой будет написано, что должно появиться в ответе. Если вывод другой — копируешь его Claude.

  1. Подключение к серверу: ssh root@IP-сервера. В первый раз спросит «Are you sure…» — ответь yes. Должна появиться строка вида root@имя-сервера:~#.
  2. Claude даст команды: установить Node.js, скачать код, создать службу, которая сама перезапускает бота.
  3. Секреты вписываешь сам. Команда nano /opt/bot/.env откроет файл. Вставь значения из «Паролей» в строки, которые подготовил Claude. Сохранить: Ctrl+O, Enter, выйти: Ctrl+X. В чат с Claude значения не копируй.
  4. Запуск и проверка журнала: Claude даст команду, в выводе должно быть что-то вроде Bot started без ошибок.
Где
Терминал на Mac → сервер клиента
Готово, когда
Бот запущен, в журнале нет ошибок, на сообщение в Telegram отвечает.

6WhatsApp (если в пакете)Вместе Клиент
  1. Клиент: верификация бизнеса в Meta Business. Срок проверки решает Meta — это время в наш срок не входит.
  2. Вместе с клиентом (созвон с показом экрана или пошаговая инструкция от Claude): Meta for Developers → приложение типа Business → продукт WhatsApp → добавить номер.
  3. Клиент создаёт постоянный токен через System User в Business Settings и присылает одноразовой ссылкой. Ещё нужны Phone Number ID и WhatsApp Business Account ID (это не секреты).
  4. Клиент направляет поддомен на IP сервера (запись A у своего регистратора домена). Claude даст команды для HTTPS-сертификата на сервере.
  5. В настройках WhatsApp → Configuration: адрес вебхука https://поддомен/webhook и проверочный токен (его придумывает Claude, хранится в .env), подписка на messages.
  6. Сначала тестируем на тестовом номере Meta, потом на рабочем номере клиента.
